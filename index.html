1

프로젝트 이해

핵심은 접수·견적·선택·일정·작업·완료·수금 확인·A/S를 한 건의 업무 기록으로 연결하고, 고객·협력업체·관리자가 같은 진행 상태와 승인·금액 이력을 보도록 만드는 것입니다. 구두로 끝나던 추가 비용 합의는 관리자·고객 승인 기록으로, 각자 기억하던 지급·수령 금액은 서로 대조되는 기록으로 바꾸겠습니다. 관리자 한 분이 시범 사업장 20곳을 운영하실 수 있도록 엇갈림을 시스템이 먼저 찾아 보여 드리고, 1차의 핵심 구조와 업무 이력을 재사용해 2차 정산·자동화로 단계적으로 확장하겠습니다.

아래 항목은 필요하실 때 눌러서 펼쳐 보실 수 있습니다.

2

핵심 수행 방안

펼쳐 보기접기
  1. 01

    둘 다 승인해야 확정되는 추가 작업

    협력업체가 원작업에 연결해 사유·금액·사진과 함께 요청하면 관리자 승인과 고객 승인을 각각 따로 기록하고, 같은 차수·금액·범위에 두 승인이 모두 있을 때만 확정해 청구 예정 금액에 합산합니다. 고객 미응답은 승인으로 처리하지 않고 「응답 기한 경과」로 남기며, 미해결 유상 추가 작업이 있으면 「완료 보류」로 멈춥니다. 미수행 추가 작업이 반려·철회로 종결되면 사유와 이력을 보존하고 고객 완료 확인을 이어갑니다. 이미 수행한 작업은 단순 철회로 기록에서 제외하지 않습니다. 금액·범위가 바뀌면 새 차수로 다시 승인받고, 전화로 받은 고객 동의는 실제 입력자와 동의 시각·방식·근거를 분리해 기록합니다.

  2. 02

    차이를 자동으로 찾아 근거와 함께 확인하는 수금 대조

    고객 지급 기록과 협력업체 수령 기록을 따로 받아 청구 예정 금액(확정 견적 + 확정 추가 작업)과 함께 자동 대조하고, 「수금 대기 / 한쪽 기록됨 / 수금 일치 / 불일치 / 청구 금액 차이 / 확인 처리됨」으로 정리합니다. 금액·일시·방법 중 다른 칸을 나란히 강조하고, 정정은 기존 기록을 고치지 않고 새 기록으로 추가해 원인과 근거를 추적합니다. 「확인 처리됨」에는 정정 후 재대조 결과 또는 관리자의 증빙 검토 결과·사유를 남기며, 관리자 사유 입력만으로 실제 수금 일치나 결제 완료로 바꾸지 않고 미해결 차이는 계속 표시합니다. 같은 요청이 두 번 들어와도 요청 고유 키로 한 번만 반영합니다.

  3. 03

    관리자 한 분을 위한 「확인 필요」 목록과 2차를 위한 기록 구조

    견적 미응답, 고객 선택·완료 확인 대기, 추가 작업 승인 대기·기한 경과, 완료 보류, 수금 미기록·불일치, A/S 접수를 한 목록에 사유·경과 시간과 함께 모으고, 각 항목에서 해당 건의 상세 화면으로 바로 이동해 처리합니다. 관련 데이터는 하나의 건 번호(Job ID)로 연결하고, 상태·승인·금액 변경 이력은 기존 기록을 덮어쓰지 않고 새 기록으로 추가합니다. 서비스 분류·질문·점검 항목과 지역·사업장 정보는 기준 데이터로 관리해, 같은 업무 기록을 활용하면서 2차 정산·구독·자동화·다지역 운영 기능을 확장하겠습니다.

작업 완료와 고객 확인의 구분「작업 중 → 협력업체 완료 보고 → 고객 확인 대기 → 고객 완료 확인 → 작업 완료」로 처리하고, 업체 보고만으로 완료하거나 고객 미응답을 자동 완료하지 않습니다. 고객의 보완 요청은 사유와 함께 업체에 전달하고 재보고 후 다시 확인받습니다. 작업 완료와 수금 상태는 따로 관리해, 수금 확인이 남아 있어도 A/S는 원작업에 연결됩니다.

[프로토타입]은 가상 데이터 기반의 제안용 설계·시연 사례입니다.

이번 과업의 프로토타입에서는 고객의 문자 인증 접수·견적 3개 비교·추가 작업 승인·완료 확인, 협력업체의 견적 자동 합계·현장 사진 업로드 재시도·완료 보고, 관리자의 「확인 필요」 목록·이중 승인과 전화 동의 대리 입력·수금 대조와 정정 기록을 하나의 접수 건으로 연결해 체험하실 수 있습니다. 실제 문자 발송·사진 저장 서버·결제와는 연결되지 않습니다.

수행 조건

펼쳐 보기접기
범위
공고의 필수 과업 전체(상세 기획·UI/UX 디자인·고객/협력업체 모바일 웹·반응형 관리자 웹·공통 API/관계형 DB·인프라 구축과 배포)를 구현합니다. 세 화면은 하나의 코드베이스와 공통 API에서 공통 기능을 재사용해 중복 개발을 줄이겠습니다. 기획 공수는 상태 정의·승인·수금 정책 확정에 집중하겠습니다.
접수·작업 기록·알림
기본안에는 서비스 분류·고정 질문을 통한 접수, 같은 휴대폰 번호 재인증을 통한 내 접수 현황·작업 이력 조회, 작업 전·후 사진과 기본 점검표 기록을 포함합니다. 견적 요청·도착·선택, 일정·승인 요청은 문자로 안내하고 발송 결과를 기록해 고객과 협력업체가 다음 할 일을 확인할 수 있도록 하겠습니다.
견적·사진 운영
최대 3개 견적의 가격·일정·포함 범위·유형·유효기간을 비교한 뒤 견적을 선택하거나 선택을 취소할 수 있게 합니다. 조건부·진단형 견적은 조건과 최종 금액에 대한 고객 동의를 확인한 뒤 본작업을 진행하며, 기본안에서는 기존 견적 버전과 고객 선택 기록으로 관리합니다. 옵션 ④는 진단 후 재견적·재승인 전용 단계와 업체 일정 충돌 방지를 추가합니다. 사진은 형식·용량 제한을 안내하고, 화면을 연 상태에서 정해진 횟수만큼 업로드를 재시도하며 수동 재전송도 제공합니다. 사진을 첨부하지 못한 경우에는 사유·메모로 대체 기록을 남깁니다. 관리자에게는 응답 마감·대체 업체 재요청·견적 공개/마감 기능을 제공합니다.
기술
화면은 React·TypeScript 반응형 모바일 웹으로 구현해 앱 설치 없이 문자 링크로 이용할 수 있게 합니다. 승인과 금액 기록을 한 묶음으로 저장하는 서버는 Java·Spring Boot로 구현하고, 데이터베이스는 별도 라이선스 비용 없이 사용할 수 있는 PostgreSQL을 사용합니다. 사진은 클라우드 객체 저장소에 보관하고, 권한 있는 사용자에게만 짧은 시간 동안 유효한 열람 주소를 제공합니다. 서버·저장소·도메인은 처음부터 귀사 명의 클라우드에 구성합니다. 홈 화면 설치형 PWA는 옵션 ⑧-6으로 구분합니다.
인수 기준
본인·전화 대리접수로 접수부터 A/S까지 전 단계 처리, 같은 차수 이중 승인 전 확정·완료 0건과 미응답 자동 승인·자동 완료 0건, 수금 불일치·한쪽 미기록 표시와 정정 전후 기록 보존, 같은 요청 반영 1회, 다른 고객·미배정 업체 접근 차단, iOS Safari·Android Chrome 360·390·430px 화면, 배포 문서만으로 재배포·백업 복원 성공을 시험합니다.
결과물·귀속
전체 소스코드(귀사 소유 저장소), DB 스키마, 운영 매뉴얼·배포 문서(다른 업체가 재배포 가능한 수준), 화면 구성도·정의서, 업무 흐름·단계 정의서, API 명세, 통합 테스트 결과를 드리며 저작권·소유권은 귀사에 귀속됩니다.

소통
